# Motorola 68000 CPU on the Sega Genesis / Mega Drive: Programming Reference

Scope: the plain MC68000 (not 68010/020+) as a Genesis homebrew author sees it. Written for an AI tutor, so every
instruction row starts with its mnemonic for grep. Cycle counts are 68000 clock periods in the form
`total(reads/writes)`; "+ea" means add the effective-address (EA) cost from the EA table in section 2.

Primary sources used throughout:
- UM = Motorola/Freescale *M68000 8-/16-/32-Bit Microprocessors User's Manual* (MC68000UM), section 2 (programming model), section 6 (exceptions), section 8 (68000 timing tables) — https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf
- PRM = Motorola *M68000 Family Programmer's Reference Manual* (1992), table 2-4 (EA categories), tables 3-18/3-19 (flags, conditions), per-instruction pages — https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf
- NGD = NeoGeo Dev Wiki "68k instructions timings" (community transcription of the UM tables) — https://wiki.neogeodev.org/index.php?title=68k_instructions_timings

## 1. Programming model: D0-D7, A0-A7 (USP/SSP), PC, SR/CCR, user vs supervisor mode

### Takeaway
The 68000 has eight 32-bit data registers (D0-D7), eight 32-bit address registers (A0-A7, where A7 is the stack pointer and is physically two registers, USP and SSP), a 32-bit PC that drives a 24-bit address bus, and a 16-bit SR whose low byte is the CCR (X N Z V C). A Genesis program starts, and normally stays, in supervisor mode.

### Cited Findings

**Registers**
- User model: 16 general 32-bit registers D0-D7 and A0-A7, a 32-bit PC, and an 8-bit condition code register (CCR). D0-D7 are used for byte, word and long data. A0-A6 and the USP serve as base addresses and software stacks. Any of the 16 can be an index register. — [UM §2.1.1](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)
- Data registers: a byte operation uses bits 7-0 and a word operation bits 15-0. Only that low part is read or changed, and the upper bits are left alone. — [UM §2.3.1](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)
- Address registers: no byte operations. As a source, a .w op uses the low word and a .l op the whole register. As a destination the WHOLE 32-bit register is always written, and a word operand is sign-extended to 32 bits first. — [UM §2.3.2](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)
- A7 is the active stack pointer: USP in user mode, SSP in supervisor mode. The supervisor model adds the SSP and the high byte of the SR. — [UM §2.1, Figs 2-1/2-2](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)
- Addresses go out on 24 address lines. The top 8 bits of a 32-bit address are ignored by the bus on every family member except the 68008. — [UM §6.2.1](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)

**Status register (SR) bit layout** — [UM §2.1.3, Fig 2-4](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)

| Bit | 15 | 14 | 13 | 12 | 11 | 10 | 9 | 8 | 7-5 | 4 | 3 | 2 | 1 | 0 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| Name | T (trace) | - | S (supervisor) | - | - | I2 | I1 | I0 | - | X | N | Z | V | C |
| Byte | system byte | | | | | | | | user byte = CCR | | | | | |

- Bits 5, 6, 7, 11, 12 and 14 are undefined or reserved. — [UM §2.1.3](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)
- CCR flags: X = extend (a copy of the carry used by ADDX/SUBX/NEGX/ROXx/ABCD/SBCD/NBCD), N = negative (result MSB), Z = zero, V = signed overflow, C = carry/borrow. — [PRM table 3-18](https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf)
- Interrupt mask I2-I0: interrupts at or below the mask level are blocked. Level 7 is non-maskable and fires on each transition into level 7. — [UM §6.3.2](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)

**User vs supervisor mode**
- S=1 means supervisor mode. Instructions that change the whole SR are privileged: MOVE to SR, ANDI/ORI/EORI to SR, RTE, STOP, RESET and MOVE USP. Running one in user mode causes a privilege-violation exception (vector 8). — [UM §6.1 and table 2-2](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)
- Every exception copies the SR, sets S=1 and clears T. — [UM §6.2.5](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)
- Reset forces supervisor state, turns tracing off and sets the interrupt mask to 7. It loads the SSP from vector 0 and the PC from vector 1. — [UM §6.3.1](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)
- 68000-specific: MOVE from SR is NOT privileged on the 68000/68008. The PRM files it under "(MC68000, MC68008)" and says it becomes privileged on later CPUs. MOVE from CCR does not exist on the 68000 (the PRM lists it for MC68010 and later only). — [PRM, MOVE from SR / MOVE from CCR pages](https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf)

### Inferences
- Common SR values on the Genesis, worked out from the bit layout (S = $2000, mask n = n×$100):
  - `move.w #$2700,sr`: supervisor mode, all interrupts masked. Use it during init and critical sections.
  - `move.w #$2300,sr`: allows levels 4 (HBlank), 6 (VBlank) and 7, and blocks level 2 (external).
  - `move.w #$2500,sr`: allows VBlank (6) only.
  - `move.w #$2000,sr` (or `#$2100`): allows all of 2, 4 and 6.
- Because reset starts in supervisor mode with mask 7, a Genesis game gets no interrupts until it lowers the mask. Almost all homebrew simply stays in supervisor mode. Dropping to user mode only adds privilege-violation traps.
- Because the bus ignores bits 31-24, `$00FF0000` and `$FFFF0000` reach the same RAM byte on the Genesis.

### Gaps
- No Genesis-specific source was found saying whether any commercial game ran in user mode. This is assumed to be rare.

## 2. Addressing modes: syntax, categories, which instructions accept which, EA cycle costs

### Takeaway
The 68000 has 12 usable EA modes (14 counting quick-immediate and implied). Each instruction accepts a category: data, memory, control or alterable, or a combination. PC-relative and immediate modes are never alterable (never a destination). EA cost runs from 0 cycles for registers to 16 for an absolute-long long-word.

### Cited Findings

**Modes, encodings and categories** — [PRM table 2-4](https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf); syntax and generation from [UM table 2-1](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)

| Mode (Motorola syntax; old-style alias) | mode/reg bits | Data | Memory | Control | Alterable | What it means |
|---|---|---|---|---|---|---|
| `Dn` | 000/n | X | | | X | data register |
| `An` | 001/n | | | | X | address register (.w/.l only) |
| `(An)` | 010/n | X | X | X | X | memory at An |
| `(An)+` | 011/n | X | X | | X | memory at An, then An += size |
| `-(An)` | 100/n | X | X | | X | An -= size, then memory at An |
| `(d16,An)`; `d16(An)` | 101/n | X | X | X | X | An + sign-extended 16-bit displacement |
| `(d8,An,Xn)`; `d8(An,Xn.w/.l)` | 110/n | X | X | X | X | An + Xn + sign-extended 8-bit displacement |
| `(xxx).W`; `$1234.w` | 111/000 | X | X | X | X | 16-bit address, sign-extended |
| `(xxx).L`; `$123456.l` | 111/001 | X | X | X | X | 32-bit address |
| `(d16,PC)`; `label(pc)` | 111/010 | X | X | X | — | PC + displacement (read-only) |
| `(d8,PC,Xn)`; `label(pc,d0.w)` | 111/011 | X | X | X | — | PC + Xn + 8-bit displacement (read-only) |
| `#<data>` | 111/100 | X | X | | — | immediate |

(The PRM's printed table shows `000` as the register field for both absolute modes. The standard encoding is absolute short = 111/000 and absolute long = 111/001, and the TST page in the same PRM shows `(xxx).L` as 111/001.)

- Postincrement and predecrement step by N = 1/2/4 for byte/word/long. If An is the stack pointer (A7) and the size is byte, N = 2, which keeps SP even. — [UM table 2-1 notes](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)
- Displacements and word-sized index registers are sign-extended to 32 bits before use. The absolute-short address is sign-extended to 32 bits. — [PRM §2.2](https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf)
- Category definitions: data = refers to data operands; memory = refers to memory; alterable = writable; control = memory operands without a size. Combined categories include "data alterable" and "memory alterable". — [PRM §2.3](https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf)
- The PRM's other modes (base displacement `(bd,An,Xn)`, memory-indirect `([bd,An],Xn,od)`, scaled index `Xn*4`) are 68020+ only and must not be taught for the Genesis. — [PRM table 2-4 / §2.4](https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf)

**Which instructions accept which categories** (from the PRM per-instruction pages; summarized)

| Instruction(s) | Source EA | Destination EA |
|---|---|---|
| MOVE | all modes (An only for .w/.l) | data alterable (no An, no PC-rel, no #) |
| MOVEA | all | An only (.w/.l) |
| ADD/SUB `<ea>,Dn` | all (An only .w/.l) | Dn |
| ADD/SUB `Dn,<ea>` | Dn | memory alterable |
| AND/OR `<ea>,Dn` | data modes (no An) | Dn |
| AND/OR `Dn,<ea>` | Dn | memory alterable |
| EOR | Dn only | data alterable |
| ADDA/SUBA/CMPA | all | An |
| CMP | all (An .w/.l) | Dn |
| ADDI/SUBI/ANDI/ORI/EORI/CMPI | # | data alterable (68000: CMPI cannot use PC-relative) |
| ADDQ/SUBQ | #1-8 | alterable (An allowed for .w/.l, no flags then) |
| CLR, NEG, NEGX, NOT, NBCD, Scc, TAS | — | data alterable |
| TST | data alterable on 68000 (An, PC-rel and # are 68020+ only — [PRM TST page](https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf)) | — |
| MULU/MULS/DIVU/DIVS/CHK | data modes (no An) | Dn |
| BTST | Dn or # bit number | data modes (incl. PC-rel) |
| BCHG/BCLR/BSET | Dn or # bit number | data alterable |
| JMP, JSR, LEA, PEA | control modes only: (An), d16(An), d8(An,Xn), abs.w, abs.l, d16(PC), d8(PC,Xn) | — |
| MOVEM regs→mem | — | control alterable, or -(An) |
| MOVEM mem→regs | control, or (An)+ | — |
| ASx/LSx/ROx/ROXx on memory | — | memory alterable, word size, shift by 1 only |
| MOVE to CCR / MOVE to SR | data modes | — |

**EA calculation times** (add to instructions marked +ea) — [UM table 8-1](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf); identical in [nvg 68000 timing](https://oldwww.nvg.ntnu.no/amiga/MC680x0_Sections/mc68000timing.HTML) and [NGD](https://wiki.neogeodev.org/index.php?title=68k_instructions_timings)

| Mode | .b/.w | .l |
|---|---|---|
| Dn, An | 0(0/0) | 0(0/0) |
| (An) | 4(1/0) | 8(2/0) |
| (An)+ | 4(1/0) | 8(2/0) |
| -(An) | 6(1/0) | 10(2/0) |
| d16(An) | 8(2/0) | 12(3/0) |
| d8(An,Xn) | 10(2/0) | 14(3/0) |
| abs.w | 8(2/0) | 12(3/0) |
| abs.l | 12(3/0) | 16(4/0) |
| d16(PC) | 8(2/0) | 12(3/0) |
| d8(PC,Xn) | 10(2/0) | 14(3/0) |
| #imm | 4(1/0) | 8(2/0) |

- The size of the index register (Xn.w or Xn.l) does not change the time. — [nvg](https://oldwww.nvg.ntnu.no/amiga/MC680x0_Sections/mc68000timing.HTML)

### Inferences
- Rule of thumb for a tutor: every extra 16-bit word an instruction must read (extension word or memory operand) costs about 4 cycles. That is why `-(An)` costs 2 more than `(An)+` and why absolute long is the most expensive way to address memory.
- d8 in indexed modes is only -128..+127. Larger table offsets need `lea table,a0` followed by `(a0,d0.w)`.
- An index written `d0` with no size is treated as `d0.w` by most Motorola-syntax assemblers, and it is sign-extended. An index of $8000 or more therefore becomes negative. This is a frequent bug with large tables.

### Gaps
- Assembler-specific syntax details, such as whether `(xxx).w` is chosen automatically, the `$`/`%` prefixes, and asm68k vs vasm vs GNU as differences, were not researched here.

## 3. The 68000 instruction set: operation, sizes, flags, cycles

### Takeaway
Below is every 68000 instruction with its sizes, flags (from PRM table 3-18 and the instruction pages) and base 68000 cycle counts (from UM section 8). The key facts for beginners: MOVEQ, ADDQ, SUBQ, LEA and register-to-register ops cost 4-8 cycles; memory operands add 4-16; MULU/MULS cost up to 70; and DIVU/DIVS cost up to 140/158.

### Cited Findings

**Flag notation** (PRM table 3-18): `*` = set from the result; `-` = not affected; `0`/`1` = cleared/set; `U` = undefined; `z` = "cleared if result is non-zero, otherwise unchanged" (sticky Z for multi-precision chains). — [PRM tables 3-18, 3-19](https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf)

**Condition codes for Bcc / DBcc / Scc** — [PRM table 3-19](https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf)

| cc | Meaning | Test | Signed/unsigned use |
|---|---|---|---|
| T | true | 1 | DBT/ST only. Bcc cannot use T (that is BRA) |
| F | false | 0 | DBF (= DBRA) / SF. Bcc cannot use F (that encoding is BSR) |
| HI | higher | !C & !Z | unsigned > |
| LS | lower or same | C \| Z | unsigned <= |
| CC (HS) | carry clear | !C | unsigned >= |
| CS (LO) | carry set | C | unsigned < |
| NE | not equal | !Z | |
| EQ | equal | Z | |
| VC / VS | overflow clear / set | !V / V | |
| PL / MI | plus / minus | !N / N | |
| GE | greater or equal | N==V | signed >= |
| LT | less than | N!=V | signed < |
| GT | greater than | !Z & N==V | signed > |
| LE | less or equal | Z \| N!=V | signed <= |

### Inferences
- MOVEM mem→reg is listed as (3+n) reads, but the instruction only needs the mask word, the next-instruction prefetch and n data reads (2+n). This is inferred from the bus counts, not from an explicit Motorola statement. It matters if the next address is a hardware register with read side effects.
- The 68000 can't do 32×32 multiply or 32/32 divide in one instruction. MULU.L, DIVU.L, DIVSL, EXTB, Bcc.L, bit-field instructions, CAS, RTD, BKPT, MOVEC/MOVES and scaled index are all 68010/020+. A tutor generating code must never emit them for the Genesis. (Basis: PRM pages flag these "MC68020... only".)
- In timing terms, the cheapest useful instructions are 4 cycles (MOVEQ, register MOVE.W/.L, ADDQ.W Dn, EXT, SWAP, TST Dn, NOP). A typical game loop instruction is 8-20 cycles.

### Gaps
- Exact data-dependent DIVU/DIVS cycle formulas were not found in the sources read. The UM only gives maxima (140/158) and says the best-to-worst spread is under 10%. Community analyses reportedly give exact formulas, but none was verified here.
- Instruction-by-instruction 68000 *encodings* (opcode bit patterns) were not tabulated. They are in the PRM if an assembler/disassembler lesson needs them.

## 4. Exceptions and the vector table ($000-$0FF), interrupts on the Genesis, address errors

### Takeaway
The first 256 bytes of a Genesis ROM are the 68000's 64 long-word vectors. Vector 0 is the initial SSP, vector 1 the entry point, and the Genesis uses autovectors at $68 (level 2, external/TH pin), $70 (level 4, HBlank) and $78 (level 6, VBlank). An address error (word or long access at an odd address) is a group-0 exception that pushes a 7-word frame. Its saved PC is imprecise, so it is effectively a crash handler.

### Cited Findings

**Vector table** — [UM table 6-2](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf); Genesis column from [gendev forum (Gigasoft: IRQ6 VBlank, IRQ4 HBlank, IRQ2 controller TH pin)](https://gendev.spritesmind.net/forum/viewtopic.php?p=24770) and [plutiedev ROM header ($100-$1FF follows the vectors)](https://plutiedev.com/rom-header)

| Vec # | Address | 68000 assignment | Genesis use |
|---|---|---|---|
| 0 | $000 | Reset: initial SSP | initial stack pointer (into work RAM) |
| 1 | $004 | Reset: initial PC | program entry point |
| 2 | $008 | Bus error | crash handler |
| 3 | $00C | Address error | crash handler (odd word/long access) |
| 4 | $010 | Illegal instruction | crash handler |
| 5 | $014 | Zero divide | crash handler |
| 6 | $018 | CHK instruction | crash handler |
| 7 | $01C | TRAPV instruction | crash handler |
| 8 | $020 | Privilege violation | crash handler |
| 9 | $024 | Trace | debugger use |
| 10 | $028 | Line 1010 ("A-line") emulator | opcodes $Axxx |
| 11 | $02C | Line 1111 ("F-line") emulator | opcodes $Fxxx |
| 12-13 | $030-$034 | reserved | — |
| 14 | $038 | reserved on 68000 (68010 format error) | — |

| 16-23 | $040-$05C | reserved | — |
| 24 | $060 | Spurious interrupt | — |

- The reset vector is 4 words (SSP then PC) and is read from supervisor program space. TRAP #n uses vector 32+n. — [UM table 6-2 notes](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)
- VBlank is level 6 (autovector $78) and HBlank is level 4 (autovector $70). The VDP is the interrupt source, and the Mega Drive answers the interrupt-acknowledge with an autovector. — search-result summaries of [Sega Retro: Mega Drive Interrupts](https://segaretro.org/Sega_Mega_Drive/Interrupts) and [gendev forum](https://gendev.spritesmind.net/forum/viewtopic.php?p=24770). Sega Retro could not be fetched directly (bot wall); the mapping is confirmed by the gendev thread.

**Exception groups and processing** — [UM §6.2.3-6.2.5, table 6-3](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)
- Group 0 (reset, address error, bus error): aborts the current instruction; processing starts within two clocks.
- Group 1 (trace, interrupt, illegal, privilege): taken before the next instruction.
- Group 2 (TRAP, TRAPV, CHK, zero divide): raised by normal execution of the instruction.
- Sequence: (1) copy SR internally, set S, clear T, and for interrupts set the mask to the level being serviced; (2) get the vector number; (3) push PC then SR on the supervisor stack (reset pushes nothing); (4) load the PC from the vector.
- Group 1/2 frame on the 68000 is 3 words: SR at (SP), PC at 2(SP). No format word (that is 68010+).
- Interrupts are checked only between instructions. A pending interrupt at or below the current mask waits. Level 7 cannot be masked. — [UM §6.3.2](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)
- A bus error or address error during exception processing for a bus error, address error or reset HALTS the CPU (double fault). Only an external reset restarts it. — [UM §6.3.9.1, §6.3.10](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)

**Address error** — [UM §6.3.10, Fig 6-7](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)
- Raised when the CPU tries to access a word or long operand, or fetch an instruction, at an odd address. It behaves like an internally generated bus error, using vector 3.
- Group-0 stack frame on the 68000 is 7 words, lowest address first:
  - SP+0: a word with R/W (bit 4: 1=read), I/N (bit 3: 0=instruction) and function code (bits 2-0)
  - SP+2: access address (long)
  - SP+6: instruction register (opcode word)
  - SP+8: SR
  - SP+10: PC (long)
- The stacked PC is "advanced 2-10 bytes beyond" the start of the faulting instruction, so the 68000 cannot simply resume. The handler is responsible for cleaning the stack. — [UM §6.3.9.1](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)
- On the Mega Drive, word/long access to an odd address causes an address error. Many early emulators don't check for it, so such bugs show up only on real hardware. — [plutiedev: Hardware issues](https://plutiedev.com/hardware-issues)

### Inferences
- A beginner-safe crash handler is `move.w #$2700,sr` followed by showing an error screen or looping forever. For the address-error and bus-error vectors, do not `rte`: the stacked PC is unreliable, and the extra 8 bytes of frame would first have to be popped (`addq.l #8,sp`).
- Since the Genesis uses no vectorized (non-auto) interrupts, the 64-vector table ends exactly where the Sega header starts at $100. An assembler source should emit 64 `dc.l` entries, then the header.
- Interrupt latency: 44 cycles of exception processing, plus up to the remaining time of the current instruction (a DIVS can delay it by ~158 cycles), plus `rte` 20 cycles. HBlank handlers on a ~488-cycle line (section 7) must therefore be very short.
- vasm/asm68k listings sometimes show `dc.l 0` for the initial SSP. Because predecrement wraps $00000000 to $FFFFFFFC, which the 24-bit bus maps to $FFFFFC, this puts the stack at the top of RAM. This is an inference from the 24-bit truncation (UM §6.2.1), not from a Genesis source.

### Gaps
- Whether the Genesis board ever asserts a 68000 BUS ERROR (/BERR) for unmapped addresses was not confirmed. Accounts vary and the topic was not covered by the sources read. Accesses to unmapped regions are generally described as locking up the machine (no DTACK) rather than raising a bus error, but this is unverified.
- The exact VDP register bits that enable HInt/VInt/external interrupts are out of scope here (they are VDP topics). A search snippet said VDP reg $00 bit 4 enables HInt and reg $01 bit 5 enables VInt; this was not verified against a primary source in this pass.

## 5. Big-endian byte order, alignment, absolute-short sign extension, address-register word writes

### Takeaway
The 68000 is big-endian: the most significant byte sits at the lowest address. Words and longs must start on EVEN addresses (2-byte alignment is enough for longs). Absolute-short addresses and word-sized address-register writes are sign-extended to 32 bits. On the Genesis, that sign extension lets `$8000.w`-`$FFFF.w` reach the top 32 KB of work RAM ($FF8000-$FFFFFF).

### Cited Findings
- Byte order: the high-order byte of a word is at the word's own (even) address and the low-order byte at the next (odd) address. A long at n (n even) has its second word at n+2. — [UM §2.4](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)
- Instructions and multi-byte data are accessed only on word (even) boundaries. — [UM §2.4](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)
- A word/long operand or instruction fetch at an odd address causes an address error. — [UM §6.3.10](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf); Genesis confirmation — [plutiedev](https://plutiedev.com/hardware-issues)
- Absolute short: the 16-bit address is sign-extended to 32 bits before use. — [PRM §2.2](https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf)
- Only 24 address bits reach the bus on the 68000. — [UM §6.2.1](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)
- Genesis work RAM is $FF0000-$FFFFFF (64 KB). — [plutiedev ROM header (RAM range field)](https://plutiedev.com/rom-header); [ChibiAkumas Genesis memory map](https://www.chibiakumas.com/68000/genesis.php)
- An address-register destination is always written in full 32 bits, and word operands are sign-extended first. — [UM §2.3.2](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)
- A .w transfer by MOVEM into ANY register sign-extends to 32 bits. — [PRM MOVEM page](https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf)
- A byte push or pop on A7 moves SP by 2 to keep it even. — [UM table 2-1 notes](https://www.nxp.com/docs/en/reference-manual/MC68000UM.pdf)

### Inferences
- Worked example: after `move.l #$12345678,$FF0000`, memory holds $FF0000=$12, $FF0001=$34, $FF0002=$56, $FF0003=$78. `move.b $FF0000,d0` gives $12 and `move.w $FF0002,d0` gives $5678.
- Absolute short on the Genesis: `$0000.w`-`$7FFF.w` → $000000-$007FFF (first 32 KB of ROM, read-only); `$8000.w`-`$FFFF.w` → $FFFF8000-$FFFFFFFF → $FF8000-$FFFFFF (top half of RAM). Variables placed at $FF8000 or higher can be accessed as `move.w d0,(Var).w`. That is 12 cycles instead of 16 for `.l` and 2 bytes smaller. (Derived from the PRM sign-extension rule + UM 24-bit bus + the plutiedev RAM map + the UM MOVE timing.)
- `movea.w #$8000,a0` gives A0 = $FFFF8000, not $00008000. `adda.w d0,a0` treats D0.w as signed, so D0 = $9000 moves A0 *backwards*. To add an unsigned 16-bit offset, zero-extend it first (`moveq #0,d1` / `move.w d0,d1` / `adda.l d1,a0`).
- Long-word variables only need even addresses on the 68000, but keeping longs 4-aligned costs nothing and eases a later port to a 68020+ (an inference, not required).
- Byte structures followed by word fields are a common source of odd addresses. Use the assembler's `even`/`align 2` directive after `dc.b` strings.

### Gaps
- None significant. Assembler directive names (`even`, `cnop 0,2`, `align`) vary by assembler and were not verified.

## 6. Speed idioms, Genesis-specific pitfalls (TAS, CLR on ports) and common beginner mistakes

### Takeaway
Most speed comes from a few habits: MOVEQ/ADDQ/SUBQ instead of immediate forms, register operands, (An)+ instead of absolute addresses, DBRA loops, `add Dn,Dn` instead of `lsl #1`, MOVEM for bulk moves, and avoiding MULU/DIVU. The two Genesis traps that bite are TAS (its write is lost on most consoles) and read-before-write instructions (CLR, Scc, MOVE from SR) hitting hardware ports.

### Cited Findings

**TAS is broken on the Genesis**
- TAS performs its test-then-set using a locked (indivisible) read-modify-write bus sequence meant for multiprocessor semaphores. — [PRM TAS page](https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf)
- On most Mega Drives TAS "doesn't write back", so it behaves roughly like `btst #7`. The Genesis model 3 VA2 does write back, behaving more like `bset #7`. — [plutiedev: Hardware issues](https://plutiedev.com/hardware-issues)
- Sega Retro says TAS uses a different bus cycle and is effectively a no-op for memory writes on MD1 and MD2. The Majesco Genesis 3 VA2 does support it, which breaks some games that wrongly use TAS (it names Gargoyles and Ex-Mutants). — [Sega Retro: Mega Drive Quirks](https://segaretro.org/Mega_Drive_Quirks) (seen via search-result summary only; direct fetch was blocked)
- The Amiga, another 68000 machine, has a similar problem. There, TAS's RMW cycle (AS held asserted between the read and the write) interacts badly with custom-chip DMA. — [Amiga Developer CD TAS note via search](https://discmaster.textfiles.com/view/18/Amiga%20Developer%20CD%20v2.1.iso/Reference/Amiga_Mail_Vol2/Archives/Plain/ja90/TAS.txt); [NGD warns against TAS on Amiga](https://wiki.neogeodev.org/index.php?title=68k_instructions_timings)

**Read-before-write instructions**
- "In the MC68000 and MC68008 a memory location is read before it is cleared" (CLR). MOVE from SR likewise reads its memory destination before writing. — [PRM CLR and MOVE from SR pages](https://www.nxp.com/docs/en/reference-manual/M68000PRM.pdf)

**Optimization tips from Genesis developers** — [SpritesMind "68000 programming optimization tips" thread](https://gendev.spritesmind.net/forum/viewtopic.php?p=31233)
- Use Scc with AND/OR/EOR to compute boolean expressions without branching (GManiac, Sik).
- Branchless counting: `tst.b (a1)+` / `seq d2` / `add.b d2,d3` inside a `dbf` loop, said to save 4 cycles per iteration over a conditional branch (Natsumi).
- `subx.b d0,d0` captures the X flag as $00/$FF, and `add.b d0,d0` restores it (gasega68k).
- `moveq #$0F,d0` / `and.b $A10001,d0` instead of `move.b $A10001,d0` / `and.b #$0F,d0` (Miquel).
- Using MOVEP to build VDP command words instead of shifts (Sik).

**Multiplication/division on the Genesis** — [plutiedev: Multiplication and division](https://plutiedev.com/multiplication-division)
- MULU/MULS are 16×16→32 with a Dn destination and a source that cannot be An. They cost 38-70 cycles depending on the source bits.
- DIVU/DIVS divide 32 by 16, giving the quotient in the low word and the remainder in the high word, truncated toward zero. They cost about 140 cycles.
- Check V after a divide (`bvs`) for quotient overflow. Test the divisor for zero first, because divide by zero raises an exception. Avoid both instructions in hot code, division especially.

**Beginner mistakes a tutor should catch**
1. Forgetting `#`: `move.w $10,d0` loads the word AT address $000010; `move.w #$10,d0` loads the number 16. `$` means hex, and decimal has no prefix.
2. `moveq` out of range: only -128..127, and always sign-extended to 32 bits. `moveq #$FF,d0` gives $FFFFFFFF (-1), not 255. For 128-255, use `move.l #200,d0`, or `moveq` + `and`. Always long size.
3. DBRA counts one extra: the body runs Dn+1 times, so load count-1 (`moveq #9,d7` gives 10 iterations). It only uses the low word: Dn.w = 0 runs once, and a counter of $FFFF runs 65,536 times. It never tests zero first.
4. CMP operand order: `cmp.w d1,d0` computes d0 - d1. `bgt` then means "d0 > d1". Use BHI/BHS(BCC)/BLO(BCS)/BLS for unsigned values (addresses, tile numbers) and BGT/BGE/BLT/BLE for signed.
5. Flags not set by address-register ops: MOVEA, ADDA, SUBA, LEA and ADDQ/SUBQ to An leave the CCR unchanged. `tst.l a0` is illegal on the 68000. Use `cmpa.w #0,a0` or `move.l a0,d0`.
6. `.w` with addresses: `movea.w`, `adda.w` and word-indexed `(a0,d0.w)` sign-extend, so values of $8000 and up become negative offsets. Use `lea` or `.l` for full addresses.
7. MULU/DIVU sizes: MULU only uses the low words but writes the full 32-bit Dn. DIVU leaves the remainder in the high word, so do `andi.l #$FFFF,d0` (or `ext.l`/`swap` handling) before using the quotient as a long. A quotient over $FFFF sets V and leaves Dn unchanged.
8. Odd addresses: any `.w`/`.l` access via an odd pointer crashes (address error). Emulators may hide this; test on hardware or an accurate emulator such as BlastEm.
9. CLR, Scc and MOVE from SR on hardware ports read first. To zero a port, write a zeroed register instead (e.g. `moveq #0,d0` / `move.w d0,(a0)`). Never use CLR, BSET/BCLR or other read-modify-write instructions on write-only or read-sensitive I/O.
10. TAS for locks: don't use it on the Genesis. On a single CPU, `bset #7,(a0)` then `bne already_taken` gives the same test-and-set semantics, because interrupts are only taken between instructions (UM §6.3.2). For locks shared with the Z80, use the Z80 bus-request protocol instead.
11. 68020+ instructions copied from tutorials (`extb.l`, `mulu.l`, `divu.l`, `(a0,d0.w*2)`, `tst.l a0`, `move ccr,d0`, `bra.l`) won't assemble for the 68000, or will run as illegal instructions.
12. `bcc.s` range: -128..+126 bytes. Branching to the very next instruction needs `.w`. Most assemblers auto-size or warn.
13. Shift counts: immediates only go 1-8. Larger counts need a register (mod 64), or `swap` for 16.
14. ABCD/SBCD chains: Z is only ever cleared, so set Z (`move #4,ccr`) and clear X before a multi-byte BCD add/sub (e.g. score counters).
15. EOR has no `eor <mem>,Dn` form. EOR's source must be a data register.
16. MOVEM.W into data registers sign-extends them to 32 bits (unlike MOVE.W, which leaves the upper half alone).

**Interrupt-safety idiom**: `move.w sr,-(sp)` / `move.w #$2700,sr` / ... / `move.w (sp)+,sr`. This works in supervisor mode on the 68000 (MOVE from SR is unprivileged there).

### Gaps
- No primary or hardware-test source was found explaining exactly WHY the Genesis drops TAS's write (bus-arbiter/gate-array behavior). The explanation that the RMW cycle with AS held across read and write isn't completed by Sega's memory logic is commonly given but unverified. Sega Retro itself marks emulator support as unknown.
- Whether the VDP control port reacts badly to the extra read from CLR was not verified from a primary source. The general rule (avoid RMW instructions on hardware registers) follows from the PRM read-before-write note.

## 7. Genesis 68000 clock (NTSC 7.670454 MHz, PAL 7.600489 MHz) and the per-frame cycle budget

### Takeaway
The 68000 runs at the master clock ÷ 7: 53.693175 MHz / 7 ≈ 7.670454 MHz (NTSC) and 53.203424 MHz / 7 ≈ 7.600489 MHz (PAL). With 3,420 master clocks per scanline, that is ~488.6 68000 cycles per line and ~128,006 cycles per NTSC frame (~59.92 Hz). PAL gives ~152,400-152,900 per frame depending on the line count (312 vs 313; sources conflict).

### Cited Findings
- Master clock 53.693175 MHz (NTSC) / 53.203424 MHz (PAL). The 68000 and YM2612 run at the master clock ÷ 7 = 7.67045357 MHz (NTSC) / 7.60048914 MHz (PAL). The Z80 and PSG run at ÷ 15 = 3.579545 / 3.546895 MHz. — [rhargreaves mega-drive-midi-interface wiki: Sound chip timings with PAL vs NTSC](https://github.com/rhargreaves/mega-drive-midi-interface/wiki/Sound-chip-timings-with-PAL-vs.-NTSC) (via search summary); exact PAL master clock 53,203,424 Hz — [gendev forum](https://gendev.spritesmind.net/forum/viewtopic.php?p=8430)
- A scanline lasts exactly 3,420 master clocks in the common video modes. In H32 that is 684 dot-clock ticks × 5; H40 reaches the same total with a different pixel-clock pattern. — [gendev: Megadrive video timings](https://gendev.spritesmind.net/forum/viewtopic.php?p=36944); [raddad772: Genesis VDP pt 3](https://raddad772.github.io/2024/07/21/genesis-vdp-pt-3.html) (via search summaries)
- Master cycles per frame: 896,040 (NTSC) and 1,067,040 (PAL). — [Sega Retro: Mega Drive technical specifications](https://segaretro.org/Sega_Mega_Drive/Technical_specifications) (search-result summary; the page itself was blocked)
- NTSC: 262 lines, 59.922 Hz. One hardware table gives PAL 312 lines, while another source says 313. — search summaries citing [Sega Retro specs](https://segaretro.org/Sega_Mega_Drive/Technical_specifications) and other pages; **conflict flagged**
- After resetting the Z80 and YM2612, wait at least 192 68000 cycles. — [plutiedev: Hardware issues](https://plutiedev.com/hardware-issues)

### Inferences (arithmetic from the cited figures)

| Quantity | NTSC | PAL |
|---|---|---|
| 68000 clock | 53,693,175 / 7 = 7,670,453.6 Hz | 53,203,424 / 7 = 7,600,489.1 Hz |
| One clock period | ≈130.4 ns | ≈131.6 ns |
| 68000 cycles per scanline | 3420 / 7 ≈ 488.57 | ≈488.57 |
| Lines per frame | 262 | 312 or 313 (conflict) |
| 68000 cycles per frame | 896,040 / 7 ≈ 128,005.7 | 1,067,040 / 7 ≈ 152,434 (312 lines) or 1,070,460 / 7 ≈ 152,923 (313 lines) |
| Frame rate | 53,693,175 / 896,040 ≈ 59.92 Hz | ≈49.86 Hz (312) / ≈49.70 Hz (313) |
| VBlank lines in 224-line mode | 262 - 224 = 38 → ≈18,566 cycles | 88-89 lines → ≈43,000 cycles |

- A 4-cycle instruction (MOVEQ, NOP) takes ≈0.52 µs on NTSC. At a realistic 8-12 cycles per instruction, a full NTSC frame is roughly 10,000-16,000 instructions. Of that, VBlank allows only ~1,500-2,300 instructions for VRAM/CRAM/VSRAM updates (DMA is usually preferred there).
- Example budgets: one DIVU (≤140) is ~29% of a scanline. A 1,000-iteration `move.l (a0)+,(a1)+` / `dbra` loop costs ~30,000 cycles (20 + 10 per iteration), which is ~23% of an NTSC frame.
- PAL machines have about 19% more CPU time per frame but run 50 frames/s, so total CPU per second is slightly *lower* (7.60 vs 7.67 MHz). Games that tie movement to frames run ~17% slower on PAL unless they compensate.

### Gaps
- PAL lines per frame (312 vs 313) is not settled by the sources reached. Sega Retro's 1,067,040 master cycles implies 312. 313 is commonly quoted elsewhere (and gives ≈49.70 Hz), but no primary Mega Drive source was confirmed in this pass.
- Real-world 68000 throughput on the Genesis is lower than these ideal figures because of bus contention: VDP DMA halts the 68000, Z80 accesses to the 68000 bus stall it, and DRAM refresh may steal cycles. No authoritative cycle-loss figure for refresh was found. Tutors should present the budget numbers as upper bounds.
- Sega Retro pages (specs, quirks, interrupts) were behind a bot wall. Their figures here come from search-engine summaries and should be re-verified if exact citations matter.
